# Sprint 5 — Estabilização e Demo Day

## Objetivo
Preparar uma versão demonstrável, documentada e coerente com o escopo real.

## Checklist de release
- [ ] Validar fluxo de acesso, perfil, busca, grupo, solicitação e decisão em ambiente publicado.
- [ ] Corrigir defeitos críticos e registrar limitações conhecidas.
- [ ] Documentar instalação, configuração, uso e arquitetura final.
- [ ] Preparar roteiro: problema → usuários → solução → processo → arquitetura → demonstração → qualidade → limites → aprendizados.
- [ ] Ensaiar apresentação e confirmar que ambiente e dados de demonstração estão prontos.
- [ ] Fazer retrospectiva e registrar próximos passos.

## Critério de saída
Versão identificada, execução reproduzível, limitações comunicadas e demonstração ponta a ponta ensaiada.
